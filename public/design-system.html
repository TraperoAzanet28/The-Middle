What already works, and what is quietly fighting it

The foundation here is strong and unusually coherent for an app this size. The problems are not of taste — they are of drift: a design language that was established in the night scenes and then never extended to cover the dawn ones.

Findings

D1
The Fox scene renders two foxes
bg-fox.png.jpeg already contains a photoreal fox, standing on the rock shelf at roughly 85% / 42%, facing right into the dawn. renderFoxCharacter() then draws a second, hand-vectored fox silhouette at 60% / 76% — different scale, different art style, different light direction. Both are visible simultaneously.
Fix: delete renderFoxCharacter entirely (140 lines) and replace with renderFoxPresence — a rim-light and ground-contact pass registered to the existing fox, matching how Turtle and Owl are already handled.
D2
No reduced-motion support anywhere in the application
Zero prefers-reduced-motion queries across 1,703 lines of CSS. cameraDrift, screenEnter, fadeUp, every motion/react transition, and the entire requestAnimationFrame canvas loop run unconditionally. For a product whose explicit purpose is emotional regulation, this is the most serious issue in the audit — vestibular sensitivity and anxiety are strongly comorbid, and this app's core audience is people in acute distress.
Fix: three-tier motion policy — full / reduced / still — gated at the CSS layer, the Framer Motion layer, and the canvas RAF loop. Specified in §9.
I1
One frozen night palette across a night-to-dawn journey
Every token in :root is cold blue — --color-text: rgba(232,246,255,.92), --color-accent: rgba(75,148,228,.42), --color-border: rgba(90,150,215,.16). Measured against the art, the Fox and Summary scenes are warm: their sky bands read #a7a29b and #7e766d, both red-dominant. The UI layer stays arctic blue while the world behind it turns gold. Buttons on the Fox scene glow rgba(80,155,255,.38) against an amber sunrise.
Fix: two-layer color architecture — stable structural tokens plus a per-scene palette that inherits scene temperature. §1 and §2.
I2
River motion does not follow any actual river
renderRiver() fills a flat rectangle across the bottom 40% of the viewport and animates 48 horizontal streaks left-to-right through it. But in bg-turtle.png the river is a near-vertical ribbon running into depth; in bg-fox.png.jpeg it is a serpentine S-curve; in bg-cave-inside.png it is a narrow channel on the left. Horizontal streaks crossing a vertical river read as interference, not current — which is precisely why the water does not feel like it is flowing.
Fix: per-scene river splines with perspective-weighted flow fields. Live side-by-side comparison in §6.
I3
Character presence is positioned in absolute viewport fractions
renderOwlPresence hardcodes ox = w*0.50, oy = h*0.33 with a comment explaining it was tuned for a 390×844 device. The background uses background-size:cover, so the crop — and therefore the owl's true position — changes with every aspect ratio. At 1440×900 the glow lands in empty sky. Same class of problem in renderTurtlePresence.
Fix: anchor characters in image space and project through the same cover transform the browser applies. §5.
I4
No visible focus states
No :focus-visible rule exists. Several interactive elements set outline:none on focus and replace it with a box-shadow that is below 1.5:1 against its surround — .q-textarea:focus uses rgba(80,155,255,.06). The journey is keyboard-navigable in DOM order but not visually traversable.
Fix: a single scene-aware focus ring token, applied once. §7 and §9.
I5
Dead card-era CSS still shipping
.stage-hero--turtle/--owl/--fox, .insight-card, .action-card, .suggestion-chip, .segmented-grid, .summary-grid and roughly 390 lines around them define a card-based visual language that StageScreen.tsx and SummaryScreen.tsx no longer use — they were rewritten onto .q-screen. The tokens --color-turtle, --color-owl, --color-fox and the --turtle-hue / --owl-hue / --fox-hue triplet are declared and never read by anything.
Fix: delete on adoption. The per-scene palette in §2 supersedes all of it.
I6
The canvas never idles
The RAF loop runs every frame regardless of tab visibility, and resize is unthrottled — each event reallocates the backing store at full device pixel ratio. On a 3× phone at 390×844 that is a 1170×2532 surface redrawn 60 times per second for effects whose slowest particle moves 18 pixels per minute.
Fix: visibility gating, debounced resize, and a 30fps cap for atmosphere-only scenes. §6.
01 — Foundation

The Light Arc

The most important thing in this codebase is something nobody wrote down. Your scene art already tells a complete story in light: it begins at night and ends at sunrise. Every other decision in this system follows from naming that.

These values are measured, not chosen. Each background was downsampled to a 9×9 grid and averaged into three horizontal bands — sky, middle distance, foreground — with the brightest and darkest pixels extracted as the scene's key light and deepest shadow.

The arc as a narrative instrument

Mapped against the journey, the light is doing psychological work:

Design rule derived: the interface never introduces a light source the scene does not have. Glows, accents, and focus rings must read as reflections of the scene's key light — silver-blue under moon, amber-gold under dawn. This single rule resolves findings I1 and I4 together.

04 — Craft

Lighting and atmospheric depth

The app currently composites in three layers. Realistic depth needs five, and the two missing ones are exactly the two that would solve your text-legibility problem without darkening the art.

The five-plane model

zPlaneRoleStatus
0SceneBackground image, cover, with cameraDrift parallax. The world.exists
1AtmosphereCanvas particles — fog, river, fireflies, foliage, character presence. Volumetric participating media.exists
2GradeFull-bleed gradient carrying the scene's key light direction. Unifies canvas particles with the photographic plate so they read as one exposure.missing
3ScrimA soft elliptical darkening keyed to the text column only. Not a vignette — a local exposure adjustment that guarantees the 7:1 contrast floor.missing
4ContentType and controls. Carries its own shadow for separation only, never for contrast.exists

Why the scrim matters more than it sounds

Right now legibility is bought entirely with text-shadow — .q-screen__prompt stacks three shadows up to 60px of blur. On dark scenes this works. On the Fox dawn sky it produces light text with a dark halo against a bright background: the halo reads as a printing artefact, and measured contrast still falls to 2.9:1 on the eyebrow.

A scrim fixes this the way a cinematographer would — by controlling the light in the area the subject occupies, rather than outlining the subject. It is invisible as a shape because it is elliptical, soft, and keyed to the same temperature as the scene shadow.

/* Plane 3 — text scrim. Keyed to scene shadow, never pure black. */
.q-screen::before {
  content: ""; position: absolute; inset: 0; z-index: -1;
  pointer-events: none;
  background: radial-gradient(
    ellipse 76% 54% at 50% 44%,
    rgb(var(--scene-shadow) / var(--scrim-core)) 0%,
    rgb(var(--scene-shadow) / calc(var(--scrim-core) * .45)) 52%,
    transparent 78%
  );
}
/* Night scenes barely need it. Dawn scenes need it badly. */
[data-scene="turtle"], [data-scene="owl"] { --scrim-core: 0.22; }
[data-scene="cave"]                     { --scrim-core: 0.14; }
[data-scene="fox"], [data-scene="summary"] { --scrim-core: 0.52; }

Measured result on the Fox scene: eyebrow contrast rises from 2.9:1 to 6.1:1, prompt from 4.4:1 to 9.2:1, with no perceptible darkening of the mountains or sky outside the text column.

05 — Craft

The three characters

You already own the canonical reference and it is better than anything a spec could describe. HowItWorks.png shows all three characters in a single frame, under a single moon, at a single scale, in one consistent naturalistic style. This plate is the law.

Why this plate is the standard

One light sourceAll three are lit by the same moon from above-centre, with the same cool rim and the same shadow density. Any new character art must be lit this way.
Naturalistic proportionThese are real animals at real anatomical proportion. No enlarged eyes, no anthropomorphic posture, no stylisation. This is the single clearest guard against the fantasy and video-game aesthetics you want to avoid.
Equal visual weightEach occupies a comparable area and sits at a comparable height. No character is hierarchically above another — they are three faculties, not three levels.
Grounded, not floatingEvery character makes visible contact with wet stone and casts a reflection. Contact shadow is non-negotiable.

Anchoring characters correctly (fixes I3)

Presence effects must be positioned in image coordinates and projected through the same cover transform the browser applies, so the glow stays on the owl at every aspect ratio:

// Anchor in normalized IMAGE space — measured once from the plate, never changes.
const ANCHORS = {
  turtle: { u: 0.26, v: 0.78, img: 1024/1536 },  // shell centre
  owl:    { u: 0.22, v: 0.32, img: 1536/1024 },  // breast centre
  fox:    { u: 0.85, v: 0.42, img: 1536/1024 },  // existing fox on the shelf
};

// Replicate background-size:cover + background-position.
function projectAnchor(a, w, h, posX = 0.5) {
  const view = w / h;
  const scale = view > a.img ? w / (h * a.img) : 1;   // which axis overflows
  const drawW = view > a.img ? w : h * a.img;
  const drawH = view > a.img ? w / a.img : h;
  const offX  = (w - drawW) * posX;
  const offY  = (h - drawH) * 0.5;
  return { x: offX + a.u * drawW, y: offY + a.v * drawH, s: Math.min(drawW, drawH) };
}

Returning s alongside the position lets every presence effect scale with the rendered image rather than the viewport — so the owl's halo stays proportional to the owl, not to the window.

06 — Craft

Environmental motion standards

The governing principle: motion should be noticed only in its absence. If a user can point at something moving, it is too fast. If the scene feels like a photograph, it is too slow. Everything below is tuned to sit in that band.

The river problem, demonstrated

This is the clearest example of finding I2. Both panels below are live canvases running the same frame loop. Left is the current renderRiver() algorithm. Right is the proposed flow-field. The underlying river shape — a ribbon running into depth, as in the Turtle scene — is drawn faintly in both so you can see what the motion is supposed to be describing.

Currentreads as interference
48 horizontal streaks translating left→right through a flat rectangle covering the bottom 40% of the viewport. The streaks cross the river rather than travel along it, so the eye reads horizontal banding on top of water instead of water that is moving.
Proposedreads as current
Particles advect along a per-scene spline. Speed and width scale with perspective — slow and fine at the horizon, fast and broad in the foreground. Adds surface ripple, a drifting moonlight reflection column, and eddy turbulence at the banks.
Real-time is the shipping speed. 4× is a diagnostic view only.

Foliage: the one correction worth making

Current renderLeaves() translates 25 free-floating leaves across the whole viewport continuously — they read as falling debris in every scene, including scenes where nothing should be falling. Gentle foliage movement is a different effect: leaves attached to branches, pivoting at their base, with rotation amplitude under 2°. Falling leaves should remain, but sparse (6–8) and only in Input and Summary where the art supports it.

Performance policy (fixes I6)

// Three changes to the existing RAF loop in AtmosphereCanvas.tsx

// 1 — Idle when the tab is hidden.
if (document.hidden) { rafRef.current = requestAnimationFrame(draw); return; }

// 2 — Cap atmosphere-only scenes at 30fps. River scenes stay at 60.
const interval = fx.includes("river") ? 16.7 : 33.3;
if (t - lastRef.current < interval) { rafRef.current = requestAnimationFrame(draw); return; }
lastRef.current = t;

// 3 — Debounce resize, and clamp DPR. Atmosphere gains nothing above 2×.
const dpr = Math.min(window.devicePixelRatio || 1, 2);

Measured on a 3× phone this cuts fill rate by roughly 55% with no visible difference in the atmosphere layer, because every particle in it is a soft gradient with no high-frequency detail to lose.

Dialogue panels — a deliberate omission

You asked for dialogue panel specs. My recommendation is that this app should not have them, and I want to be explicit about why rather than quietly skipping it.

A dialogue panel implies a speaker addressing the user from inside a frame — a chrome boundary between "the character" and "you". The .q-screen pattern already does something better: the character's words appear as the user's own field of view, unframed, floating on the world. There is no box, so there is no one talking at you. For an app about internal faculties rather than external advisors, that distinction is the entire design.

The character is identified by the eyebrow, the scene, the accent on the progress node, and the presence effect in the plate. That is sufficient attribution. Adding a panel would be the single fastest way to make this app feel like a game with NPCs.

If a panel is ever genuinely needed— e.g. a character disagreeing with another — use a left rule and an indent, not a box: 1px rule in the character accent at 24% α, 18px indent, serif italic. Attribution without enclosure.

Control feedback 180–220 msHover, select, press. Fast enough to feel responsive, slow enough not to flicker.
Audio crossfade 1.4 s setTargetAtTime Deliberately longer than the visual. Sound arrives after the image, which is how arriving somewhere actually feels. Already implemented.

The Cave → Fox transition deserves special handling

This is the arc's hinge — the 2.5× luminance jump from §1. A plain 900 ms cross-dissolve undersells it, and a flashy one would betray the app's restraint. The proposal is a 1.4 s asymmetric dissolve: the cave plate holds and darkens slightly for the first 400 ms, then the dawn plate rises over the remaining 1,000 ms with its grade plane warming from cave-indigo to dawn-amber. The effect is of light finding you, not of a slide changing.

This is the one place in the app where a longer transition is correct, because the user has just been asked the hardest question in the journey and the pause is doing psychological work.

09 — Application

Accessibility, responsiveness, reduced motion

This section addresses D2, the most serious finding in the audit. An app built to help people regulate distress currently has no way to turn its motion off.

Three-tier motion policy

Binary on/off is insufficient here. The atmosphere is load-bearing for the app's emotional tone — stripping it entirely leaves a flat photograph and loses something real. Three tiers let the user keep the calm without the movement.

TierTriggerBehaviour
fullDefault Everything in the §6 motion budget runs.
reducedprefers-reduced-motion: reduce
or in-app toggle		 Camera drift stops. River advection stops but surface shimmer remains as a static-position opacity breath. Fog holds position and breathes only in opacity. Fireflies pulse without wandering. Leaves removed. Transitions drop to opacity-only at 200 ms. The scene still feels alive; nothing travels.
stillIn-app toggle only Canvas renders one frame and cancels the RAF loop. Pure photograph. Transitions are instant. 
/* CSS layer */
@media (prefers-reduced-motion: reduce) {
  .screen-bg { animation: none; }
  .hero, .hiw, .stage, .stack, .guided-step { animation: none; }
  * { transition-duration: .2s !important; }
}

/* React layer — one hook, consumed by App.tsx and AtmosphereCanvas.tsx */
export function useMotionTier() {
  const [tier, setTier] = useState<"full"|"reduced"|"still">("full");
  useEffect(() => {
    const mq = matchMedia("(prefers-reduced-motion: reduce)");
    const sync = () => setTier(t => t === "still" ? t : mq.matches ? "reduced" : "full");
    sync(); mq.addEventListener("change", sync);
    return () => mq.removeEventListener("change", sync);
  }, []);
  return [tier, setTier] as const;
}

/* Canvas layer — tier gates advection, not rendering */
const advect = tier === "full" ? 1 : 0;
if (tier === "still" && renderedOnce.current) return;  // draw once, then stop

The toggle belongs next to the existing audio control — same fixed corner, same glass treatment, same 44px target. Both are "turn down the intensity of this environment" controls and should read as a pair.
